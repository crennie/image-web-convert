# Quality Requirements

| Concern                    | Current expectation and acceptance evidence                                                                                                                                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recovery                   | Before listening, the API reconciles operation state and committed outputs. A valid completed output survives restart; a processing file without valid commit becomes interrupted. API process E2E tests cover abrupt and graceful restarts.                            |
| Partial results            | A failed or cancelled sibling does not remove a committed output. Individual and ZIP downloads serve available outputs; the snapshot exposes per-file outcomes. API and browser E2E tests cover partial batches.                                                        |
| Bounded work               | Defaults admit at most 3 nonterminal operations, 2 upload transports, and 1 active conversion per API process. Each manifest is limited to 20 files, 20,000,000 bytes per file, and 500,000,000 declared bytes total. Limits are configurable in `apps/api/src/env.ts`. |
| Authorization              | Conversion status, upload, cancellation, metadata, and downloads use the session bearer token. The persisted session holds a token hash. API process E2E tests cover invalid and expired access.                                                                        |
| Availability during expiry | Session cleanup waits for active conversion and download leases. The fixed default lifetime is 15 minutes; expired operation directories are swept after active use settles. Process and runtime tests cover leases.                                                    |
| Readiness                  | `/readyz` reports ready only after startup recovery and while the conversion runtime can accept work; storage mutation faults stop scheduling/readiness.                                                                                                                |
| Browser state              | The browser reports upload bytes separately from backend file states, polls authoritative snapshots, and reconciles uncertain transfer failures. Browser E2E tests exercise interrupted uploads and cancellation.                                                       |

These are current design targets and checks, not a claim of service-level availability or a hard timeout for native image processing. The [project README](../../../README.md) documents the detailed limits and validation commands.
