# Quality requirements

These expectations describe the current architecture and its limits. Environment values are defaults, not service-level guarantees. See the [root README](../../../README.md#limits-deadlines-and-storage) for the full settings table and validation commands.

| Concern                  | Concrete expectation and verification point                                                                                                                                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Access control           | The API checks a session bearer token and fixed expiry before operation and download access; upload admission happens before multipart parsing. API lifecycle tests cover authorization and expiry.                                                                                               |
| Bounded admission        | Defaults allow at most 3 nonterminal operations, 2 concurrent upload transports, and 1 active conversion per API process. A manifest is limited to 20 files, 20,000,000 bytes per file, and 500,000,000 declared bytes total. API tests cover effective limits and contention.                    |
| Recoverability           | Startup finishes recovery before listening. A valid output with matching receipt and fingerprint survives restart; an interrupted processing slot with no receipt fails as `processing_interrupted`. Corrupt evidence isolates the session. API process tests cover abrupt and graceful restarts. |
| Partial-result integrity | A file failure or user cancellation does not roll back earlier committed siblings. Downloads check completed state and commit evidence; ZIPs include available requested outputs in requested order. API and browser end-to-end tests cover partial results and downloads.                        |
| Client consistency       | Status snapshots are authoritative and revisioned. Browser polling normally runs every second and backs off on connection errors; a network error alone does not mark a conversion failed. Browser tests cover retry and cancellation behavior.                                                   |
| Resource deadlines       | Defaults are 60 seconds upload idle, 5 minutes upload total, 120 seconds per-file conversion, and 10 seconds shutdown grace. A conversion timeout is cooperative: the worker slot and input remain owned until the native invocation settles.                                                     |

Sharp's pixel ceiling defaults to 200,000,000 input pixels and the output dimension ceiling to 8192. HEIC preprocessing runs before Sharp's limits apply and can consume additional memory and CPU. The current process does not guarantee a hard wall-clock cutoff for native encoding; that would require separate process isolation.
