# Use-case and test-coverage inventory

## Boundary and reading guide

This inventory covers the current `/conversion` browser workflow, the public session/conversion/file API, and the API lifecycle behavior that determines whether a user's files can be converted or retrieved. Actors are the person using the browser, the browser client, and the API process during startup or shutdown. Environments include the built browser with a real API, a separately started API process, and focused in-process tests. Source and test paths below are relative to the repository root.

The old synchronous upload flow and implementation plans are excluded as active product behavior. The unmounted legacy conversion page and its upload hook have been removed. The retired upload route and downloads for already sealed legacy sessions remain in scope as compatibility behavior. Infrastructure setup, generic UI primitives, telemetry, and future distributed processing are outside this use-case boundary. Refreshing or reopening a tab cannot resume a batch because browser credentials are not persisted. Page-exit cancellation is best effort. Sharp/native and HEIC work do not have hard wall-clock termination; the current design has one API process per storage root.

The [JSON inventory](use-case-inventory.json) is the portable case and evidence map; this document is its readable summary. A source key resolves to a repository-relative path; an evidence key resolves to an exact test title, layer, environment, and asserted outcome below. **Direct** means a real browser or separately started API process asserts the result. **Focused** means only an in-process or mocked browser test asserts it. These labels describe evidence depth, while the `Coverage` column gives the verdict required by the [method](use-case-inventory-method.md). Test execution results belong in test reports.

## Coverage limits

- All 67 in-scope cases have matching assertions. The API process test for UC-051 observes clean staging immediately after the production entrypoint reports readiness; it does not instrument the exact instant the listening socket opens.
- UC-065–066 assert the configured-origin HTTP contract in a separately started API process; no deployed cross-origin browser environment was exercised.
- UC-041 has direct API process evidence for a conversion lease. Its download lease remains covered by the focused runtime test.
- Real browser E2E validates default WebP and selected JPEG, PNG, and AVIF downloads, plus partial, retry, and cancellation paths. Mocked browser integration assertions do not establish API behavior.
- The architecture and README state that refresh is not a resume feature and that page-exit cancellation can be lost. These are documented limits, not missing use cases.
